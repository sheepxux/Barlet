# Barlet 技术方案

Barlet 1.0 是一个本机 Mac 应用。没有服务器，没有账号，也没有数据库进程。两个人通过进程内的 Swift 接口协作，数据写在用户自己的「应用程序支持」目录里。

## 选型

| 决定 | 选择 | 原因 |
| --- | --- | --- |
| 语言和 UI | Swift 6、SwiftUI，窗口用 AppKit | 系统玻璃和菜单栏图标都在这两套框架里 |
| 最低系统 | macOS 26.0 | `glassEffect` 和 `NSGlassEffectView` 从 macOS 26 开始提供 |
| 开发工具 | Xcode 27 | 当前机器是 Xcode 27.2，接口以这套 SDK 为准 |
| 窗口 | 无边框 `NSPanel`，加上 `NSHostingView` | 胶囊要浮在所有空间上，并且不能抢走当前应用的键盘焦点 |
| 玻璃 | `Glass.regular` | 深色外观由系统算。不用 `NSVisualEffectView` 仿一层模糊 |
| 音量 | Core Audio，默认输出设备的虚拟主音量 | 公开接口，能读也能写 |
| 亮度 | IOKit 的显示器亮度参数，只针对内建显示器 | 调不了就告诉界面隐藏按钮。不使用私有的 DisplayServices |
| 媒体键 | 系统媒体事件 | 播放和切歌由系统交给当前播放器。不链接 MediaRemote |
| 快捷键 | 辅助功能权限下的按键事件 | 预设本质是「替用户按该应用的快捷键」 |
| 前台应用 | `NSWorkspace` 的激活通知 | 只拿 bundle identifier |
| 登录启动 | `SMAppService` | 系统提供的登录项，不写旧的 LaunchAgent |
| 持久化 | 一份带版本号的 JSON | 数据量就是几十个按钮。不引入 SwiftData、SQLite 或服务器 |
| 分发 | Developer ID + `notarytool` + dmg | 团队 `Q77SUT63T9`，钥匙串配置 `dev-island-notary` |
| 更新 | 落地页上的一个静态 `version.json` | 应用只读这个文件。P1，失败就当没有更新 |

11 月 1 日先验证一件事：无边框、不抢焦点的面板里，系统玻璃能否采到背后的桌面。采不到就当天改窗口的样式掩码和层级，功能先不加。验证不过，不用模糊视图冒充玻璃。

## 架构

应用分成两层。界面层画胶囊和设置。动作层执行按下之后的事。两边都只依赖下面这些类型，类型的定义以 [接口文档](接口文档.md) 为准。

```text
菜单栏图标 ── 显示 / 隐藏 / 设置 / 退出
        │
        ▼
NSPanel（透明、所有空间、全屏幕辅助、不抢键盘焦点）
        │
        ▼
胶囊视图
        ├── 前导钮          只反映「正在展开」这一个界面状态
        ├── 应用区          读取当前 bundle id 和本机文档里的按钮
        └── 系统条          按下后调用 ActionRunning
                │
                ▼
        ActionRunning（动作层）
        ├── 音量 / 亮度
        ├── 媒体事件
        └── 快捷键，以及辅助功能是否已授权

FrontAppObserving ── 只向上报告 bundle id
BarletDocument    ── 本机 JSON，界面层读写，动作层不写
```

界面层拥有窗口、玻璃、三个区域的布局、展开和收起、设置窗口、菜单栏、落地页和最终的签名公证。

动作层拥有音量、亮度、媒体事件、快捷键、授权查询，以及六个预设的初始数据。动作层用一个不带玻璃的测试台自己验收，不等胶囊。

设置里录到的新快捷键仍然是动作层的 `KeyChord`。界面层负责录制时的按键捕获，然后写成这个类型。

所有对界面可见的调用都在主线程。动作层如果内部要碰 Core Audio 或 IOKit，自己切换线程，返回时回到主线程。

## 数据设计

没有数据库服务器，也没有多用户。本机一个文件：

```text
~/Library/Application Support/Barlet/Barlet.json
```

写入时先写到同目录的临时文件，再替换原文件，避免写到一半退出后文件损坏。读到不认识的 `schemaVersion` 时，不覆盖原文件，胶囊只用内置预设。

```json
{
  "schemaVersion": 1,
  "settings": {
    "launchAtLogin": false
  },
  "profiles": {
    "com.apple.Safari": {
      "buttons": [
        {
          "id": "7E2C1A40-3B5D-4F8A-9C1E-6D0A2B4F8E11",
          "title": "后退",
          "symbol": "chevron.backward",
          "enabled": true,
          "action": {
            "keystroke": {
              "key": "[",
              "modifiers": ["command"]
            }
          }
        }
      ]
    }
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 目前是 `1`。以后加字段就加版本，并在读取时迁移 |
| `settings.launchAtLogin` | 和 `SMAppService` 的注册状态一起维护。以系统登录项的真实状态为准，这个字段是界面上的记录 |
| `profiles` | 键是 bundle id。缺这个键时用内置预设。键存在但 `buttons` 为空时，应用区留空 |
| `buttons[].id` | UUID，排序和隐藏都认这个 id |
| `buttons[].symbol` | SF Symbol 名称 |
| `buttons[].enabled` | `false` 的按钮不出现在胶囊上，但留在设置里 |
| `action` | 与 Swift 自动合成的 `Codable` 一致，四种之一：`{"keystroke":{"key":"[","modifiers":["command"]}}`、`{"media":"playPause"}`、`{"setVolume":0.4}`、`{"setBrightness":0.8}` |
| `action.keystroke.key` | 快捷键的字符，例如 `[`、`R`、`+` |
| `action.keystroke.modifiers` | `command`、`shift`、`option`、`control` 的子集 |
| `action.media` | `playPause`、`next`、`previous`、`mute` |

系统条的组成是固定的，不写进这个文件。用户在 1.0 不能增删系统条上的项。

音量和亮度的当前值不入库，每次从系统读。

内置预设在动作层的代码里，不放进 JSON。用户第一次改某个应用时，界面层把当时的内置列表抄进 `profiles`，之后以文件为准。

## 权限

快捷键使用 `AXIsProcessTrusted` 判断。未授权时 `perform` 返回 `needsAccessibility`，不发送按键。界面层据此显示 F-13 的说明。音量、亮度和媒体键在未授权时仍要成功。

## 分发

日常开发用 Xcode 直接运行。发布只在 11 月 7 日做：用团队 `Q77SUT63T9` 的 Developer ID Application 签名，用 `dev-island-notary` 公证，staple 到 dmg 上。落地页和 dmg 放在公开地址，源码仓库保持私有。

P1 的 `version.json` 放在落地页同一域名下：

```json
{
  "version": "1.0.0",
  "downloadURL": "https://example.com/Barlet.dmg"
}
```

正式域名确定前，这个地址写在应用的一个常量里。应用比较版本号，新于自身才打开 `downloadURL`。这个文件不是账号接口，也不携带用户信息。
